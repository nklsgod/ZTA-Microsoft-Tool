ZT Workshop Report Patcher

Merges your team's status/priority/tag edits (from a zt-framework-config-*.json export, e.g. one produced or edited with zt-task-manager.html) into a copy of your downloaded Zero Trust Workshop - Progress Report.htm — adding a status/priority/tag filter bar directly inside the report. Nothing is uploaded anywhere and your original files are never modified; this produces a new file to download.

Scope: the report your team downloads doesn't include its original stylesheet/script files, so it normally opens unstyled and non-interactive. Most of the report's colors are actually already baked into the HTML as inline styles (Microsoft just didn't ship the layout CSS alongside the plain download), so this patch supplies matching layout CSS — header, roadmap cards, status colors, progress bars — to bring it back close to the original look, restores the collapsed/expand behavior for the pillar task lists, and adds the new status/priority/tag filter bar on top.

How this survives the round trip: team priority/team/feature number/link/free text/tags are all parsed out of each task's existing notes field using the Status | Prio N | Team | FeatureNr | Link | Free text #tag format (the trailing free text field is optional) — a plain string the official importer already accepts. This patcher reads that JSON, matches each task by its Task ID + pillar to the corresponding item in the report, and updates that item's status badge and adds priority/team/tag chips + a new filter bar. The report keeps a strict Content-Security-Policy (no unsafe-inline scripts); the injected filter logic is instead allowlisted by its exact SHA-256 hash, computed automatically each time you generate a file, so the page's script security isn't weakened.
  • Only tasks already present as overrides in your JSON are updated; tasks never touched in either tool keep whatever status the report already showed.
  • Workshop Notes is rebuilt entirely from the JSON's notes/tags — live, not frozen at export time. A "Blocked tasks" risk card is added the same way. The report's other Top Risks cards (completion percentages, unstarted P0 counts) are left as the original export's snapshot, since computing those accurately needs the full task catalog/priority list, which isn't available outside the official tool.
  • The "Filter by Pillar" buttons are restored, scoped to the Implementation Roadmap section; the summary cards (Task Summary, Status Distribution) still show all pillars regardless of that filter.
  • Re-running this on an already-patched report is blocked — always start from a fresh export.
